# 把应用逻辑留在主机上

在围棋闯关（兄弟仓库的围棋应用）()里攒下的经验。这个应用里最有价值的结构性
决定，跟设备本身无关 —— 它是关于**哪些模块被允许知道设备的存在**。

## 分界线画在哪

`main/` 里有六个模块**不依赖 ESP-IDF、也不依赖 LVGL** 就能编译：

| 模块 | 管什么 |
| --- | --- |
| `wq_engine` | 围棋规则：气、提子、禁自杀、倒扑、简单劫 |
| `wq_session` | 关卡状态机：题面、作答、选择、终局 |
| `wq_progress` | 存档 blob：星级打包、解锁链、校验和 |
| `wq_content` | 生成的关卡表 |
| `wq_wrap` | 中文折行 |
| `wq_volume` | 音量档位表与它的算术 |

这条线以上的东西 —— 页面、控件、按键、存储、声音 —— 都 include 了 ESP-IDF 或 LVGL，
只在设备上测。

判断一个模块有没有站对边的办法是机械的：**它能不能只用宿主编译器编过？** 能，
它就可以有一个秒级的测试。要是它得有块板子才有意思，那它就属于线的上方。

这么做换来的是：`test_wq_session` 把 **154 关全部打通到底**，`test_wq_engine` 把
**134 条正解路径（280 手）全部重放**，而这两个测试加起来跑完不到一秒。如果每发现
"第 87 关过不去"都要等一次固件构建，迭代一次就是几分钟。

## 让两份实现从构造上就一致，然后证明它

关卡数据跨了两种语言：`extract_levels.mjs`（JavaScript，求值网页版的 TypeScript）
产出 `levels.txt`，`tools/weiqi/content.py`（Python）重新解析、重新校验它，然后生成
C 表。**同一套校验规则的两份独立实现，迟早会分家。**

两个机制让它们老实：

- **规则是刻意镜像的，而中间那个文件就是契约。** `levels.txt` 是唯一的事实来源，
  两边都不许凭空造数据。抽取器只写一次，之后除非给 `--force`，否则拒绝覆盖。
- **最关键的部分在真正要紧的地方重新校验一次。** 把 19x19 局面裁进 9x9 窗口，
  可能把一关从有解变成无解，所以抽取器会在**裁剪后**的棋盘上用完整规则重放每一条
  正解路径。`content.py` 在生成 C 的路上再查一遍同样的结构不变量，而 `test_wq_engine`
  会**用设备自己的 C 引擎**把同一批路径重放第三遍。三遍，每一遍抓一类不同的错。

第三遍最要紧：它是唯一一个跑着设备将来真正要执行的那份规则代码的。

## 测拒绝路径，不只是测顺利路径

存档格式是这条最能体现价值的地方。`wq_progress` 把星级按每关两位打包，外加一个
Fletcher 校验和；它的测试把这份数据**所有可能出错的方式**都断言了一遍：

- 魔数不对的 blob
- 版本号来自未来的 blob
- 校验和与载荷对不上的 blob
- 在记录中间被截断的 blob
- 关卡下标越过关卡库末尾
- 星级值超出打包范围

每一种都必须产生一个明确的拒绝，而不是被悄悄夹到一个值上。「失败时不要改动输出」
是一条测试能检查的契约，而且值得检查：一份写了一半、被设备读回去的存档，比一个
清清楚楚的失败糟糕得多。

同样的思路也出现在内容解析器里：缺键、陌生键、重复键、坐标落在窗口外、
正解路径不是从声明那一方开始 —— 全部中止。

## 测试要连真实数据，不是连一份副本

折行测试不带几个样例字符串。它遍历**生成表里的每一条题面和每一道题干**，逐条断言：
在 13 字每行下折得进缓冲、没有一行超预算、没有一行以收尾标点开头。

差别不在于"更彻底"本身。一份抄来的样例只能证明算法在**你已经想到的那几种情况**上
是对的。而真实的关卡库证明它在**第 154 关**上也是对的 —— 那一关是别人写的。

## 让整条管线可复现，于是"重跑一次"是 diff，不是惊吓

这个应用的构建里没有随机，这是刻意的。154 关是从 3564 关里确定性挑出来的，
抽取是对网页版数据的确定性求值，而每个生成器都是 `levels.txt` 的纯函数。

这条性质值得守住，因为它正是 `--check` 有意义的前提：如果 `gen_content.py --check`
失败了，**唯一**可能的解释就是有人改了关卡库却没重新生成 —— 而不是某个随机种子挪了位。
一条连自己的输出都复现不出来的管线，没法告诉你某个变化是不是你想要的。
