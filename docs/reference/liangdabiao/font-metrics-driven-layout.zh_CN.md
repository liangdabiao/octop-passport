# 让字库度量决定版式

在围棋闯关（兄弟仓库的围棋应用）()里攒下的经验。这个应用里所有的版式 bug，
都出自一个**猜出来的数字**而不是**量出来的数字**。解法是先量一次、把算术写下来，
然后让编译器永远替你检查。

## 先量字库，再摆东西

「一行放得下几个字」不是感觉，是一道除法 —— 但前提是**字形前进宽度等于字号**。
Noto Sans CJK SC 的汉字是全角，前进宽度确实等于字号，所以这道除法是精确的：

```c
#define WQ_CHARS_HEADLINE 6   /* 32px：210 / 32 */
#define WQ_CHARS_BODY     8   /* 24px：210 / 24 */
#define WQ_CHARS_SMALL   13   /* 16px：210 / 16 */
```

（行高也是同样量出来的：16px → 20，24px → 29，32px → 38。）

**要量，不要假设。** 「前进宽度等于字号」是**这一款字体**的性质，它是被验证过之后
才被信任的。换一款比例字体，整个文件就不成立了。

## 同一段文字的两种形态，两种都要上限

同一段关卡文字会出现在两个地方，预算不同 —— 而你写生成器的时候，只会盯着其中一个：

- **题面页**放着说明，在一个滚动容器里，上限 **240 字**；
- **选择题作答页**放着题干，上限 **190 字**，每个选项 **10 字**。

只卡第一种，于是一道很长的选择题题干会在生成期过关，然后在设备上溢出。两个都是
`tools/weiqi/content.py` 里的常量，生成器拒绝输出超过其中任何一个的关卡。

## 折行缓冲按最费的调用方开，不按平均

折行缓冲必须装得下最长的那条输入**折完之后**的形态，而折行本身每行还要多一个换行。
按"典型题面"的长度去开缓冲，结果就是：153 关都好，第 154 关被悄悄截断。

同一条规矩也适用于**字节与字符**那个陷阱：一个 UTF-8 汉字是 **3 个字节**，但是
**1 个字符**。按「240 字符」开出来的缓冲是 720 字节 —— 且这个数还得在换行符和结尾
符之前就留出来。弄错的表现是：文字说到一半就停住。

## 每个 `snprintf` 缓冲区按最宽的转换形态开，并写明理由

这条容易跳过，因为失败既罕见又难看：缓冲区要按**这个转换能产生的最宽值**开，
而不是按你**预期会遇到**的最宽值。`%d` 带符号最宽 11 个字符，`%u` 最宽 10 个。
把推导写在声明旁边的注释里 —— 否则一年后没人回答得了"这里为什么是 16 不是 8"。

## 把生成的预算钉在编译期

内容上限住在生成的头部里，版式常量住在 `main/wq_layout.h` 里。它们是同一个数字的
两端，而唯一能让它们老实待着的办法，是让编译器去比：

```c
_Static_assert(WQ_OPTION_TEXT_MAX_CHARS <= WQ_CHARS_SMALL,
               "选项文字再也放不进 16px 的行了");
```

于是改字号、改正文宽、改内容上限而没同步另一边，**直接编译不过**。这就是全部要点：
这层关系只声明一次，而且声明在编译器会读的地方。

## 页面预算集中写在一处

`main/wq_layout.h` 刻意不依赖 LVGL。页面代码和宿主测试都 include 它，于是两边看到
的是同一批数字：

```c
#define WQ_BODY_TOP     WQ_BAR_H                 /* 36  */
#define WQ_BODY_BOTTOM  (WQ_PAGE_H - WQ_HINT_H)  /* 284 */
#define WQ_BODY_H       (WQ_BODY_BOTTOM - WQ_BODY_TOP)  /* 248 */
```

在某个页面文件里抄一份这些数字，就是两边开始分家的起点。既然这个常量头没有任何依赖，
就没有理由去抄。

## 纵向预算同样要断言 —— 以及「能滚」不等于「滚得到」

两种截图和评审都看不出来的失败：

**纵向算术需要自己的断言。** 横向预算有生成器和折行测试两道关；纵向的通常只写在
注释里 —— 而 `y` 值算错的表现是**那个元素干脆不在那儿**。这个世界地图页摆了 7 行
32px 加 4px 间隔：`7 × 32 + 6 × 4 = 248`，正好等于正文高度，而第一版算出来是 252。
一条编译期断言当场把它拦下：

```c
_Static_assert(WQ_WORLD_ROWS * WQ_WORLD_ROW_H + (WQ_WORLD_ROWS - 1) * WQ_WORLD_GAP
               <= WQ_BODY_H, "最后一行章节会被裁掉");
```

**而且：可滚动的容器必须有一个键能滚它。** 这台机器只有三个键、没有触摸，所以每一块
可滚动区域都需要一个键来移动它。检查方法每屏只有一句话：**这块区域在屏上的时候，
三个物理键各做什么？** 一个把所有按键原样转给状态机、而那个阶段只认确定键的页面，
就有一个谁也够不着的滚动容器 —— 后半截内容在代码里完美，在设备上不存在。

反过来还有一条约束：**上下键已经被别的东西占用的页面，就不能靠滚动兜底** ——
它的内容上限必须是真的放得下的硬上限。
